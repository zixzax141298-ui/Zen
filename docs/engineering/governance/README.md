# Engineering Governance Documents

These documents supplement, and do not replace, the repository's root governance files:

1. `AGENTS.md`
2. `AI_RULES.yaml`
3. `RULES.md`
4. `SECURITY.md` for security-sensitive work

The Repository Owner is the final authority. These standards describe Owner-approved working practices; they do not create an authority above the Owner. No agent or automation may grant itself additional permission or reinterpret an ambiguous instruction as approval.

Use:
- `OWNER_AUTHORITY_AND_CHANGE_CONTROL.md` for authority, authorization scope, and approval boundaries.
- `WORKSPACE_AND_CHANGE_HYGIENE.md` for clean workspace and minimal justified diffs.
- `PR_LIFECYCLE_AND_SELF_REVIEW.md` for preparation, review, and PR status.
- `OWNER_REPORT_STANDARD.md` for evidence-based completion reports.

A document's presence does not prove that a process is automated or enforced. Report actual behavior and evidence only.
